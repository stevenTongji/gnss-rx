6告诉 Git 你是谁

Git 每存一次快照都要记录"谁在什么时候改的"。不先自报家门，后面 commit 会直接报错。

6.1 执行

打开终端（Command + 空格 → 输入 Terminal → 回车），把下面三行改成你自己的信息后粘贴：

git config --global user.name "张三" git config --global user.email "zhangsan@example.com" git config --global init.defaultBranch main
  • name 填什么：真名或常用 ID 都行。它会永久刻在每一次 commit 记录里，面试官点进仓库看得到——建议用真名拼音（如 Zhang San），显得正式。
  • email 填什么：必须和 GitHub 注册邮箱一致，否则 GitHub 上不会把你的提交关联到你的头像，绿点会算不到你头上。
  • 第三条是把默认分支名设为 main（现在业界的叫法）。你的仓库当前已经是 main，这条只是给以后新建的仓库兜底。

6.2 确认写进去了

git config --global user.name git config --global user.email
应该看到
张三
zhangsan@example.com
填错了怎么办：不用慌，再敲一次同样的命令就会覆盖。想删掉某一项就用 git config --global --unset user.name。

7注册 GitHub、领学生包、配 SSH

这一步分三件独立的事，按顺序做完。

7.1 注册账号

打开 github.com → Sign up，用邮箱注册。

用户名要想清楚再定。它会变成你仓库链接的一部分（github.com/你的用户名/gnss-rx），而这个链接要印在简历上。建议用真名拼音或固定 ID（如 zhangsan、steven-wang），别用 user123456 这种。以后改名字链接会失效，很麻烦。

7.2 领学生包（别跳过，免费的东西）

注册完立刻去 github.com/education → Get student benefits：

  1. 学校填 Tongji University
  2. 邮箱填同济教育邮箱（@tongji.edu.cn）——这是审核的关键，用个人邮箱容易被拒
  3. 上传能证明在校身份的材料：学生证照片或学信网截图都行
  4. 通常 1-3 天出结果
通过后你能免费拿到 GitHub Copilot（AI 写代码助手，市价每月 10 美元）。做 C++ 移植和调环路参数时它能帮你省下大量时间。这是合法的学生额度，不用白不用。通过后按提示在 VS Code 里装 Copilot 插件并登录即可。

7.3 生成 SSH 密钥

SSH 密钥相当于"你这台电脑的身份证"。配好之后，以后传代码不用每次输密码。

# 邮箱换成你刚才填的那个 ssh-keygen -t ed25519 -C "zhangsan@example.com"

接下来会连问三个问题，全部直接按回车（共三次）：

会看到这些提示，一路回车即可
Enter file in which to save the key (/Users/steven/.ssh/id_ed25519): ← 回车
Enter passphrase (empty for no passphrase): ← 回车
Enter same passphrase again: ← 回车
为什么建议不设密码（直接回车）：设了密码，以后每次 push 都要输一遍，对新手是纯粹的摩擦。你的电脑有开机密码保护，这个风险可以接受。如果以后想加，随时能改。

完成后把公钥复制到剪贴板（这条命令没有任何输出，是正常现象）：

pbcopy < ~/.ssh/id_ed25519.pub

7.4 把公钥贴到 GitHub

  1. GitHub 网页右上角点头像 → Settings
  2. 左侧菜单找 SSH and GPG keys
  3. 点右上绿色按钮 New SSH key
  4. Title 随便填，比如 MacBook Air（方便以后区分哪台机器）
  5. Key type 保持默认的 Authentication Key
  6. Key 那个大框里按 Command + V 粘贴（刚才已经复制到剪贴板了）
  7. 点 Add SSH key，可能要输一次 GitHub 密码确认

7.5 让 Mac 记住这把钥匙 + 测试连通

eval "$(ssh-agent -s)" cat >> ~/.ssh/config <<'EOF' Host github.com AddKeysToAgent yes UseKeychain yes IdentityFile ~/.ssh/id_ed25519 EOF ssh-add --apple-use-keychain ~/.ssh/id_ed25519

然后测试：

ssh -T git@github.com
第一次会问这句话，输入 yes 再回车
The authenticity of host 'github.com (140.82.113.4)' can't be established.
Are you sure you want to continue connecting (yes/no)? yes
成功的话最后一行长这样（你的用户名会显示在 Hi 后面）
Hi zhangsan! You've successfully authenticated, but GitHub does not provide shell access.
如果看到 Permission denied (publickey)：说明公钥没贴对。回到 7.3 重新执行 pbcopy，再回 GitHub 删掉旧 key 重新加一次。注意别复制成私钥（id_ed25519，没有 .pub 后缀的那个）——那个绝不能外传。

8第一次推送

先在网页上建一个"空仓库"，再把本地代码推上去。

8.1 在 GitHub 网页建仓库

  1. GitHub 首页右上角点 + → New repository
  2. Repository name 填 gnss-rx
  3. 选 Public（为什么见下面说明）
  4. 三个复选框全部不要勾：Add a README file、Add .gitignore、Choose a license——你本地已经有了，勾了会导致两边冲突、push 失败
  5. 点 Create repository
为什么选 Public：你做这个项目的目的就是把链接放进简历，私有仓库等于没有。面试官点进去看的是 commit 是否连续、README 是否讲得清楚、代码有没有注释。唯一例外：涉及导师在研课题、未发表论文、合作方未公开代码的，一律留本地或开私有仓库。

建好后页面会停留在一个"Quick setup"界面，先别急着复制它给的命令，看 8.2。

8.3 关联远程仓库并推送

把 yourname 换成你的 GitHub 用户名（就是 7.1 定的那个）：

cd ~/Developer/gnss-rx git remote add origin git@github.com:yourname/gnss-rx.git git branch -M main git push -u origin main
成功的话最后几行长这样
Enumerating objects: 20, done.
Writing objects: 100% (20/20), done.
To github.com:yourname/gnss-rx.git
 * [new branch] main -> main
branch 'main' set up to track 'origin/main'.
注意：一定要用 SSH 地址（git@github.com: 开头），不要用 HTTPS（https://github.com/ 开头）。用 HTTPS 的话，push 时会要求输用户名和密码，而 GitHub 早就不接受账号密码登录了，只会反复失败。万一填错了，用这条改回来：
git remote set-url origin git@github.com:yourname/gnss-rx.git

→从此以后的日常

你只需要记住一条命令就够了。

git add -A && git commit -m "说明这次改了什么" && git push
  • 什么时候敲：每跑通一个小东西就敲一次。比如"跟踪环锁定 4 颗星""画出第一张误差 CDF 图"。
  • 为什么强调小步：这是你的求职证据链。面试官看仓库时，10 月一条"实现 DLL 环路"、11 月一条"加入载波辅助"，比最后一次性上传 2000 行代码可信得多——连续的小绿点是"我真的做了两个月"的唯一客观证据。
  • 提交说明的格式（业界通用）：feat: 新功能 / fix: 修 bug / docs: 改文档 / refactor: 重构。
  • 习惯养成：push 之前扫一眼 git status，能拦掉 99% 的误传。

0先回答你最关心的问题：要不要换游戏本

结论先给，免得白折腾。

不用换。项目 A 全程在 Mac 上做，你的 M4 + 16 GB 完全够。
理由：捕获算法本质是 FFT，1 ms 数据才 4092 个采样点、几百 KB；实测在 M4 上把 32 颗卫星 × 25 个多普勒频点全搜一遍只要 0.15 秒。内存占用峰值不到 100 MB。这活儿对机器几乎没有要求。
Mac 上唯一的小摩擦
  • 自己用 RTL-SDR 采真实信号：驱动和工具链在 Windows 上更成熟。Mac 也能做（brew install librtlsdr），但教程少、坑多。
  • 应对办法：这一步是"加分项"不是"必做项"。真要采，用游戏本采完把 .bin 拷回 Mac 处理就行——采集只要一次，处理永远在 Mac 上。
什么时候才该考虑游戏本
  • 等你做到项目 C（LEO NTN 链路仿真 / 通感一体化），如果涉及大规模蒙特卡洛（几千次链路级仿真），可以扔到游戏本后台跑。
  • 或者导师给了带 CUDA 的仿真代码——Mac 没有 NVIDIA 显卡，跑不了 CUDA。
  • 但那是研二的事，现在不要为此分心。

然后配 SSH 密钥——它相当于"你这台电脑的身份证"，配好之后每次传代码不用输密码：

# 生成密钥（邮箱换成你的）。接下来连续按 3 次回车，不要设密码 ssh-keygen -t ed25519 -C "你的邮箱@example.com" # 把公钥复制到剪贴板 pbcopy < ~/.ssh/id_ed25519.pub

然后：GitHub 网页右上角头像 → Settings → 左侧 SSH and GPG keys → New SSH key → Title 随便填（比如 "MacBook Air"）→ Key 那一栏 Command+V 粘贴 → Add SSH key。

最后再让 Mac 记住这把钥匙（避免重启后又要重来）：

eval "$(ssh-agent -s)" cat >> ~/.ssh/config <<'EOF' Host github.com AddKeysToAgent yes UseKeychain yes IdentityFile ~/.ssh/id_ed25519 EOF ssh-add --apple-use-keychain ~/.ssh/id_ed25519

验证连通（第一次会问 yes/no，输入 yes 回车）：

ssh -T git@github.com

看到 Hi 你的用户名! You've successfully authenticated... 就成了。

3Git 的三个动作，以及什么时候用

你只需要记住三个命令，就能覆盖 95% 的日常。

命令它在干什么什么时候敲
git add -A把改动的文件放进"待打包清单"每次提交前
git commit -m "说明"给当前代码拍一张快照，附一句说明每跑通一个小东西就拍一张。比如"跟踪环锁定 4 颗星""画出第一张误差 CDF 图"
git push把本地快照上传到 GitHub每天收工前一次，或者攒 2-3 个 commit 一次
为什么强调"小步提交"
  • 它是你的求职证据链。面试官看仓库时，一条 10 月的 commit 写"实现 DLL 环路"，一条 11 月的写"加入载波辅助"，比最后一次性上传 2000 行代码可信得多——连续的小绿点是"我真的做了两个月"的唯一客观证据。
  • 它也是你的后悔药。改崩了，git log 找到昨天的编号，git checkout 编号 . 就回去了。

日常三连可以写成一行：

git add -A && git commit -m "说明这次改了什么" && git push

提交说明建议用这个格式（业界通用，显得专业）：

feat: 新功能 —— feat: 加入 PLL 载波跟踪环 fix: 修 bug —— fix: 修正码相位搜索的边界溢出 docs: 改文档 —— docs: 补充 README 的数据下载说明 refactor: 重构 —— refactor: 把环路参数抽成配置结构体

4三个红线（现在知道比以后补救便宜）

① 数据文件绝不进 Git。
中频采样数据动辄几百 MB（上海交大那套原始 IF 是 70 GB 级别），而 GitHub 单文件硬上限 100 MB，超过 50 MB 就会警告。
项目里的 .gitignore 已经把 *.bin / *.dat / *.mat / data/raw/* 全部排除了。万一哪天你手动 add 了大文件导致 push 失败，先 git rm --cached 那个文件，再重新 commit。
② 导师课题的未公开代码 / 未发表论文内容，不要放公开仓库。
你要放的是自己从零写的学习项目。凡是涉及实验室在研项目、未公开数据、合作方代码的，一律留在本地或私有仓库。这条踩了不是丢工作，是学术事故。
③ push 之前，先看一眼 git status。
它会列出"即将被传上去的文件"。养成扫一眼的习惯，能拦掉 99% 的误传（比如把 200 MB 的数据、或者含密码的配置文件传上去）。

6卡住了怎么办

先试这三招
  • 看报错最后一行。Python 报错是倒着读的，最关键的信息在最底下。
  • 把错误信息整段复制去搜。90% 的问题 Stack Overflow 上都有，而且你大概率不是第一个踩的人。
  • 用 Copilot / AI 解释。学生包里的 Copilot 可以直接问"这段代码为什么报错"，把报错贴给它。
几个高概率的坑
  • command not found: uv → 没走 Step 3，或者新开终端没加载 PATH；重开一个终端窗口再试。
  • No module named numpy → 你用了系统 Python 而不是项目虚拟环境。进项目目录后用 uv run python xxx.py，别直接 python xxx.py。
  • Permission denied (publickey) → SSH 没配好，回 Step 7 重做一遍 ssh -T git@github.com 验证。
  • 捕获不到卫星 → 九成是采样率或中频填错了。换数据集时这两个值是必须改的常量。
